关于

氢计划 · AeroPlan

应用简介

纯本地的日程与行程工具：日历、议程、行程表、计划、日记、天气与黄历。没有账号，也没有服务端。

提醒由系统本地通知调度，应用关闭或锁屏后仍会触发。

数据存放

条目、计划、分类、日记、偏好与同意记录只保存在本机：优先 IndexedDB，不可用时退回 localStorage。没有服务器副本。

日记里的图片与文件只存进本应用自己的 IndexedDB，不写入相册、不申请存储权限、不联网、不做云端同步。IndexedDB 不可用时，日记文字仍可保存，附件功能会提示「当前环境不支持附件」。

卸载应用会删除全部本地内容；换机前请先导出备份。

网络请求与数据去向

只有天气与地点搜索会联网，且只发送搜索关键词或所选地点的坐标（保留 3 位小数，约 100 米精度）。

收件方只有：Open-Meteo（天气）、Photon（地点搜索，基于 OpenStreetMap 数据）。

不会发送日程正文、备注、分类、备份内容、账号、通讯录、相片或设备型号；应用没有统计、广告或崩溃上报 SDK。

权限与系统限制

通知：用于到点提醒；拒绝后仍可使用，但收不到提醒。

闹钟与提醒（Android 12/12L）：用于准时触发；Android 13 及以上由系统自动授予，没有单独开关。

日历（可选，默认关闭）：只有你在「权限管理」里打开「同时写入系统日历」后才会申请读写权限。开启后，带提醒的条目写入专用日历「AeroPlan 提醒」，提醒由系统日历负责，不联网；关闭开关会清空该专用日历里由本应用写入的事件，不会改动你原有的任何日历。

振动：用于轻触反馈，可随时关闭。本版本不申请存储与定位权限：备份经系统保存/分享面板完成，导入由你手动选择文件。

国产系统的自启动、后台清理与省电策略可能拦截提醒；需要时请在系统设置里允许本应用自启动/后台运行，并把省电策略设为「不限制」。应用无法把自己加入这些白名单，只能由你手动开启。重要事项请同时在系统闹钟里设一次提醒。

系统日历和本地通知用的是同一套 AlarmManager。区别在于系统日历是系统应用、在系统白名单里，不受省电与自启动策略限制，所以更可靠；它并不是用了特殊的推送通道。

备份文件

备份是未加密的 JSON，含条目、计划、分类、日记、偏好与同意记录。

默认备份不含附件本体，只有文件名、大小与类型；需要连图片一起带走时，在「备份数据」弹窗里选择「包含附件」，体积可能很大，导出前会估算并再次确认。

备份文件中的日记为明文，含附件时体积很大，请妥善保管。

生成后交给系统保存或分享面板，应用内不留副本，临时文件用完即删；文件可能被他人看到，请存放在可信位置。

数据来源与许可

天气与预报：Open-Meteo，仅发送所选地点坐标。地点搜索：Photon（OpenStreetMap 数据，版权归贡献者，ODbL）。请求都由设备直达，不经过本项目中转。

字体与图标许可

站酷小薇 ZCOOL XiaoWei 与 Cormorant Garamond：SIL Open Font License 1.1；Lucide 图标：ISC License。字体、图标、应用图标与启动图都随应用本地打包，不从网络加载。

签名与安装包

官方签名指纹：生成新密钥后填入（见 README）

从非官方渠道获得、或签名指纹不一致的安装包，可能已被修改，请勿使用。

客户端没有「不可破解的加密」：混淆只提高改动成本，真正阻止第三方改包的是系统的签名校验。

0.9.1

开始使用前

氢计划用手机的系统通知提醒你安排的事。通知只在你自己的手机上生成，不会上传到任何地方。

通知与提醒 检测中…

提醒由系统排程，关掉应用或锁屏后也会按时通知。权限、通知渠道、精确闹钟与排程数量可以在「通知自查」里逐项查看。

系统拒绝了通知权限。可以打开手机「设置 → 应用 → 氢计划 → 通知」把通知打开，再回到这里点下面的按钮重新检查。

同时写入系统日历

开启后，带提醒的日程/待办会写入专用日历「AeroPlan 提醒」，由系统日历负责提醒，更不容易被后台策略拦住。默认关闭。

重要事项请同时在系统闹钟里设一次；部分系统会限制后台运行。

通知自查

这里列出权限原始返回值、通知渠道、全部条目的提醒存储值与本轮排程结果。权限已允许、渠道已创建、排程数大于 0 仍不响时，多半是系统后台限制。

十秒自检

点一次按钮：用与正式提醒完全相同的参数排一条 10 秒后的通知，并实时记录监听事件、系统队列、已送达列表与当前是否在前台。

怎么判读：

① 收到事件 + 已送达有记录 + 屏幕无横幅 → 投递成功但被系统拦截显示（渠道/横幅/勿扰）。

② 收到事件 + 已送达为空 → 投递失败，重点查小图标与提示音。

③ 未收到事件 + 队列在等待后被清空 → 闹钟被系统吞掉（后台策略）。

④ 未收到事件 + 队列里仍有该条 → 排程未生效。

原生通道

这条通道不经过 Capacitor 插件：由 App 内的 AlarmManager 直接排程、广播接收后自己发通知。

检测中…
